# Codex Reset Watch · 额度重置预警

**有可信新消息时提醒，不必反复刷新社交平台寻找 Codex 额度消息。**

王向野整理的 ChatGPT 网页定时任务模板，关注 ChatGPT / Codex 订阅额度重置、Banked Reset、Credits 和相关活动。

> GitHub 保存说明与提示词，实际监测需要在支持联网搜索和定时任务的 ChatGPT 环境中配置。本模板不直接读取个人剩余额度，不自动购买或兑换重置。

## 为什么做这个

额度消息散落在官方公告、社交平台回复和社区讨论中。这份任务把「找消息 → 核验来源 → 区分类型 → 去重 → 提醒」整理成可以复用的流程。

## 快速开始

1. 打开支持联网搜索和 Scheduled / 定时任务的 ChatGPT 网页环境。
2. 复制下方「每轮执行提示词」，调整关注套餐与时区。
3. 先要求「仅试运行一次，不创建定时任务」，核对来源和输出。
4. 再发送下方「创建任务指令」，确认任务已启用、运行频率和时区正确。
5. 检查 ChatGPT 与手机系统的通知设置，并查看前几轮实际运行结果。

定时任务和工具是否可用取决于账户及工作区，具体选项以界面为准。模型采用当前默认设置，无需 API Key。官方建议先测试提示词，再检查最初几轮运行：[Scheduled tasks](https://learn.chatgpt.com/docs/automations)。

### 创建任务指令（只发送一次）

> 请把下面的「每轮执行提示词」设为当前聊天中的长期条件监测任务，名称为「OpenAI Codex 额度监测」。使用 Asia/Shanghai 时区，每小时运行一次。若环境不支持此频率，说明可用频率，不要声称创建成功。仅在符合通知条件时提醒，无变化保持安静。模型与推理设置使用当前默认值。创建后核对任务是否启用、频率和时区。不要创建重复任务。

创建指令与每轮执行内容分开，避免每次运行重新创建任务。可根据需要调整时区与频率。

## 每轮执行提示词

复制以下分隔线之间的全部内容。

---

你正在执行一次 ChatGPT / Codex 订阅额度条件监测。仅完成本轮检查，不创建、复制或修改定时任务。

### 用户配置

- 关注套餐：不限定。分别说明涉及的套餐，不猜测我的套餐。
- 输出时区：Asia/Shanghai。保留来源原始时间与时区，再换算。
- 提醒语言：简体中文。
- 通知条件：新的可信信号、重要进展或更正。

### 1. 目标与范围

尽可能提前发现 ChatGPT / Codex 订阅产品的 usage reset、weekly limit、free/bonus credits、extra usage、临时提高 limits、banked reset、paid reset，以及邀请、推荐或活跃用户奖励。

排除只涉及 OpenAI API 的 rate limits、API credits 和开发者账户余额。这不是普通新闻汇总，也不是个人额度仪表盘。

### 2. 增量检查

首次回看最近 24 小时；后续从上次成功检查时间继续，保留约 2 小时重叠窗口。先轻量扫描，发现候选信号后再深入核验。不反复总结旧消息，不复制长篇原文。

在当前任务可用上下文中保留上次成功检查时间、来源覆盖情况和事件指纹，不把内部记录作为用户通知。仅成功检查后更新对应来源的时间。

若上下文或去重记录不可用，重建基线，不把旧消息当作新事件，不声称完整去重。来源打不开不等于没有消息；记录缺失覆盖范围，不编造内容。

### 3. Tibo 早期信号

优先查看 Thibault “Tibo” Sottiaux 的公开账号 @thsottiaux：https://x.com/thsottiaux 。结合账号资料、链接和上下文核验身份，不只看昵称。

关注 reset、credits、bonus、extra usage、increased limits、incoming、soon、landing、tomorrow、milestone、reward 等表达，但不要机械匹配。阅读父帖和回复，分清是在谈额度、产品发布还是其他事情。

本人有可信额度信号而尚未正式公告时，使用【Tibo 一级早期信号｜尚未完全官宣】。区分原话与推断，说明原始时间、可能事件、额度类型、预计时间、适用范围、可信度及原始链接。

玩笑、附和或模糊暗示不能写成已发放或确定承诺。无法确定时明确写「不确定」。后续正式确认时再发一次实质更新。

### 4. 官方来源

检查 OpenAI 官方网站/博客、ChatGPT 与 Codex 更新说明、Help Center、Status、官方社交账号，以及可核验身份的 OpenAI 员工公开消息。

API 文档只用于辨别产品范围，不把 API-only 活动误报为订阅福利。官方明确公告优先；摘要、转载、截图或无法打开的片段不能单独构成官方确认。

原始来源不可读时说明限制，降低可信度；证据不足则不通知。没有时区的「今天午夜」「明天」等表达不能擅自换算成确定时间。

### 5. 社区级信号

轻量检查 OpenAI Developer Community、GitHub Codex issues/discussions、Reddit 等公开社区，关注多人额度恢复、reset timer 改变、新 Credits/奖励/购买入口等现象。

单个用户、单张截图、单个 issue、旧消息再传播或未核实传闻不能触发通知。至少满足一项：

- 多个相互独立用户在相近时间报告一致现象；
- 不同平台有可核验且独立的一致报告；
- 社区报告与 Tibo 原始消息相互印证；
- 社区现象能由官方页面、帮助文档或可核验员工消息印证。

转载同一来源不算独立证据。说明实际核对的样本、数量和来源，不虚构数量。满足条件时使用【社区级早期信号｜尚未官方确认】。

社区体验不能证明所有账户适用，也不能证明已查明服务端原因。

### 6. 额度分类

- A｜直接 Usage Reset：核验是否立即刷新当前窗口、发生时间及剩余额度处理。
- B｜Credits / Bonus Credits：核验用途、有效期、是否可储存及与订阅额度的关系。
- C｜临时提高 Usage Limits：核验提高的额度、速率或倍率及持续时间。
- D｜活动奖励：核验奖励内容、参与条件和适用范围。
- E｜Banked Reset：单独核验储存、领取期限、兑换效果与限制，不与 Credits 混称。
- F｜Paid Reset 或入口变化：核验付费要求、资格限制和账户差异。

不明确就写「类型尚未确认」。这些分类不是任何现行活动的保证。普通周期重置、临时全局重置和手动兑换必须分开；别人的周期不能证明我的重置时间。

### 7. 提前预警与使用建议

有可信证据表明现有 usage 可能即将直接刷新时，不必等到账后才提醒。使用【重要｜Codex 额度可能即将 Reset】，说明信号级别、预计时间范围、时区确定性、适用套餐、是否可能覆盖剩余额度及依据。

本任务不能读取我的个人剩余额度，不得声称知道当前百分比或个人账户已经到账。公开公告不能证明我的账户实际发生重置。

只根据已核验规则给条件化建议。若确有直接 Reset 临近且我有真实工作，可建议安排原本需要完成的工作；不要鼓励为清空额度制造无意义任务。

若奖励可储存，说明无需为了此次活动提前消耗当前额度，同时核对有效期和使用规则。不购买、不兑换、不消耗重置券，不修改账户配置，不索取登录凭据。

### 8. 去重与更正

事件指纹包含来源账号/原始链接、发布时间、类型和核心事实。同一事件只提醒一次。

只有官方确认、时间变明确、适用范围/数量/规则变化、类型确认或事件取消/证伪时更新，并指出「相比上次新增了什么」。

官方确认使用【OpenAI 官方确认】；证伪或取消使用【更正｜此前额度消息已被证伪或取消】。每小时重新搜到旧消息不构成新事件。

### 9. 提醒格式

- 【信号级别】早期信号 / 社区信号 / 官方确认 / 更正
- 【发生了什么】一句话概述
- 【预计时间】原始时间与时区、换算结果；不确定就明确说明
- 【涉及用户】已核验套餐/范围；不明确则写尚未明确
- 【额度类型】A–F 或尚未确认
- 【是否需要行动】简短、条件化建议；不以消耗额度为目标
- 【可信度】高/中/低及依据，区分事件存在与适用个人账户的可信度
- 【证据】原始来源、社区交叉验证及无法访问的来源
- 【原始链接】可直接打开的链接和发布时间
- 【本次新增】仅重要更新时填写

### 10. 最终输出

无符合条件的新信息时静默结束，不输出「暂无变化」「检查完成」、占位符、心跳或内部日志。

需要提醒时用自然中文，解释必要的英文术语。不通过 Gmail 或其他邮箱发送消息，不调用外部发信工具；使用任务所在平台的通知能力，是否启用由用户设置。

## 使用边界

- 个人实际余额、可兑换奖励和重置时间，以自己的 Usage 页面为准。
- 静默是提示词规则；系统级完成提醒是否出现、手机是否送达，需要查看前几轮实际表现。
- 定时运行会使用平台资源；按需求调整频率。调度延迟和来源访问限制会影响时效。
- 去重依赖任务上下文，本模板没有独立数据库。
- 定期在 Scheduled 检查任务是否仍启用、最近运行是否正常。
- 网页任务不能直接访问电脑文件夹；提示词需存入任务或可访问的上传上下文。
